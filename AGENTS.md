# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Start with `docs/ARCHITECTURE.md` (module boundaries, enforced by `src/architecture.test.ts`); the room's contract is `docs/ROOM.md`, the visual spec `docs/ART-DIRECTION.md` (its "The room's UI" section covers everything outside the TV and computer screens).
- `pnpm check` before committing; give each checkout its own e2e server with `E2E_PORT=<port> pnpm e2e` (the `@frames` tests run alone after the rest).
- Bundle budgets are tight and itemised in `bundle-budgets.json` (`pnpm report:bundle`); a new lazy chunk or worker needs a row in `scripts/bundle-report.mjs` and a budget. A lazy chunk must import types only and get runtime values through a kit (`posterKit.ts`, `spotlightKit.ts`, `gen/genKit.ts` for three.js under `src/room`; `world/nav/kit.ts` for the game's mouse play), or Rolldown splits shared modules onto the critical path; likewise a module the room's chunk and the generators both import at runtime lands in the room's chunk, so keep such modules small (`gen/kit/vec.ts`, `gen/props/lavaWax.ts`, `gen/roomSpec.ts`) and generators out of them.
- Performance is measured, not guessed: `node scripts/perf/profile.mjs` (a production build on the visitor's path, desktop or phone-sized, Chromium or WebKit, GPU time per frame and per pass) and `scripts/perf/counterfactuals.mjs` (each effect off in turn). The room draws at a quality tier and scale its governor moves with measured frame times (`src/room/stage/quality.ts`, docs/ROOM.md › Quality); a new effect must keep working on every tier, and anything per-pixel belongs in the tier table rather than behind a device check. `?debug=perf` shows the tier and frame rate on a phone.
- The room is generated in code, for every visitor: no model or texture is shipped (`src/room/gen/`, docs/ROOM.md › The generated room). A worker builds the geometry, a one-time GPU bake lights it, the TV view's part first (the room is `ready` then) and the rest behind the game. The room's chunk starts that worker as it is created (the same generators are the lazy `roomBuilder` chunk where a worker cannot be had). Anything under `gen/` but `genKit.ts` imports three's types only (the worker must not carry three.js); what the room's code needs of a prop's place goes in `gen/roomSpec.ts` (plain numbers, held to the generators by `gen.test.ts`); a new prop needs a triangle budget, a static light goes into `gen/rig.ts` (never a per-frame shader term on baked surfaces), and shader noise uses the integer hashes of `gen/kit/hash.ts`.
- The room is one picture, held to its art bible (`docs/ROOM-ART-DIRECTION.md`: the colour script, each view's focal order, every light's job, the material families); a change to a prop, a surface, a light or a poster is judged in the room's views on both framings and the top and lowest tier (`node scripts/gen-shots.mjs`, `--flights` for the camera on its way), not by itself. The colour of light lives in three places that must agree: `gen/rig.ts` with the finish in `atmosphere/moods.ts`, the posters' painted light (`posters/wall/light.ts`) and the startup still's sampled colours (`index.html`).
- A generated prop is judged at arm's length too: `node scripts/gen-closeups.mjs` shoots it from fixed cameras (`--studio` for form and albedo whatever the rig, `--still` to compare two runs pixel for pixel), and it builds to `sink.detail` so lower tiers get a lighter version (docs/ROOM.md › The generated room › Finely made props, Detail by tier). Desk-corner props join the `desk` mesh, floor-standing ones rest on `FLOOR`. A part with a line thinner than a pixel across the room is made twice (`sink.making`): `built` as geometry for multisampled frames, `drawn` flat with the line in a chart's surface function, a texel inside the chart's edge, for frames without; the built making must stay pixel-identical while multisampled (docs/ROOM.md › Lines without multisampling).
- The walls' posters are code too (`src/room/posters`, docs/ROOM.md › Posters): the layout and geometry in `wall/`, original designs painted by a worker in `paint/` (a design draws one sheet in millimetres at 4–8 texels/cm, so bold shapes; `node scripts/poster-sheet.mjs` paints the contact sheet). The wall, its worker and its painter import nothing of the room's chunk at runtime; the painter's canvas is CPU-backed (`willReadFrequently`), since a worker's bitmap of GPU pixels uploads black.
- The lit room draws all the time through `RenderLoop.pace` (sixty frames a second on the display's own frames, docs/ROOM.md › Frames): motion rides those frames (`loop.ride`) or animates, and never paces frames of its own. A mesh that sets its own colour says so with `userData.ownColour`, so the spotlight leaves it alone (the radio's LCD).
- e2e pins shader program counts (`e2e/programs.ts`); anything that compiles a program must be counted there (`renderer.compile` prepares invisible meshes too).
- Screens are light, not bloom: the TV lights the room as an area light (`src/room/tv/screenLight.ts`, drawn by the finish's existing shaders) and a display glares only at its brightest pixels (docs/ROOM.md › The TV's light); a screen-space veil of the picture over the set reads as fake (`e2e/tv-light.spec.ts` guards it). Any other light that changes goes the same way, into the finish's surface shader (`src/room/atmosphere/RoomGloss.ts`) rather than a three.js light; one that never changes is baked, as the opal lamp and the bare-bulb lamp beside the TV are (docs/ROOM.md › The opal lamp, The bulb lamp).
- The stage's cursor is a named `RoomCursor` (`idle`/`enter`/`leave`/`press`, over the game's picture its pixel arrow `play-arrow` or hand `play`, and over a level's play the game's own `walk`/`jump`/`attack` from `GameSurface.cursor`) drawn through `--room-cursor-*` custom properties that `app/cursors/cursors.css` themes (docs/ROOM.md › Cursors); tests read `dataset.cursor`, not `style.cursor`. The game shows its hand only where a step's hit test called `input.clickable(hit)`/`pointsAt(rect)` (docs/ARCHITECTURE.md › GameSurface): anything new a click acts on must hit-test through them. E2e tests that play a level act through the page's mouse and read where things are from `__arcade.level()` (dev-only, `game/scenes/level/probe.ts`).
- The page opens on a still of the TV view that a script inlined in `index.html` draws (`src/app/startup/still`, `scripts/stillPlugin.ts`; docs/ROOM.md › Startup): outlines generated from the room's generators, each surface's light a grid of colours sampled from the live room with its set on and its picture black, and over the grids the room's own render as one image (`public/startup/still-*.avif`/`.webp`, written by the build, never by hand, fetched once the room is ready), placed by a copy of the TV view's camera in plain numbers, held to the room in colour (CIEDE2000) and outline by `e2e/still.spec.ts`. After a change to the set, the cabinet, the lamps, the plant, their light, the finish's vignette or the framing run `pnpm build:still` (it builds, serves on port 4720 and opens Chromium on the GPU; `--no-sample` for outlines only); `scripts/still/still.test.ts` fails while it is stale. What the picture lights is the still's last drawing, coloured by `--tube` on `#tv-still`. Every byte of that script is in the first response, and every element it writes is styled before the first paint: keep `inline.ts`, `draw.ts` and `camera.ts` small and free of imports, and a surface's light a field (three elements), never a gradient element a stop.
- A browser with no GPU gets the résumé alone, nothing of the room or the game (docs/ROOM.md › No GPU): the startup gate (`src/app/startup/gate`, inlined into the head by `scripts/gatePlugin.ts`) decides before the first paint, and the site's entry is imported by the page's last script rather than named in the markup. `?host=cv` forces the résumé; `?host=room`/`flat` skip the question, and a page opened on software WebGL must name one or it is the résumé (the e2e suite's `ROOM_GL=swiftshader` run is served ungated). The résumé page (`src/app/cv`) is markup the build renders, built apart from the site: keep React and anything of the site out of it (`cvPage` in the bundle report).
- The game's art is code, not image files: every picture is a `*.art.ts` module holding its pixels as a string (docs/ARCHITECTURE.md › Art in code). A PNG written under `src/game` becomes one with `pnpm build:art` (a test fails on a PNG left there) and `pnpm build:art --export src/game` writes the PNGs back for the generators under `tools/` (tools/art/README.md); never edit a module by hand, and keep art out of the first script (a look's own chunk, or `levels/art/pictures.ts`). The cursors stay PNGs, which the build slims (`scripts/pngSlim.ts`), so never hand-optimise them.
- A first visit starts muted (`defaultSession().muted`); an e2e test that needs sound seeds `localStorage['reo-leo:session']` with `{ version: 1, muted: false }` (see `e2e/radio-flow.spec.ts` › `open`). Radio tracks are held to 5 MB each, 16 MB in all, by `src/content/radio/validate.ts` (`pnpm verify:radio`).
- A canvas painted once must paint again on its `contextrestored`: a GPU process reset (laptop sleep, display change) wipes every 2D canvas, `willReadFrequently` ones too, and the restored WebGL context uploads them blank (the room's baked light goes too, and is baked again). Room code uses `src/room/stage/canvasRestore.ts`, engine/game caches go through `paintCanvas` (`src/engine/gfx/canvas.ts`); docs/ROOM.md › Lost canvases, and `e2e/gpu-reset.spec.ts` crashes the GPU with CDP `Browser.crashGpuProcess` in its own browser.
- Reduced motion in this project means no transitions or animations at all (things appear and go), and entrance animations use `backwards` fill so finished ones leave `document.getAnimations()` empty (several e2e tests wait for it).
